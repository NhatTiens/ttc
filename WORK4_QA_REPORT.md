## Persistence after Next restart

After the API smoke test, restart Next.js and set the previously printed order/ticket IDs:

```text
WORK4_EXPECT_ORDER=<order-id>
WORK4_EXPECT_DEPOSIT=<deposit-id>
WORK4_EXPECT_TICKET=<ticket-id>
WORK4_EXPECT_PHONE=<phone-marker>
```

Then run:

```bash
npm run qa:work4:persistence
```

This verifies those resources are still readable after a Next process restart.

## Known limitations

1. No external provider integration; new orders remain `PENDING`.
2. No real payment gateway; deposits remain `PENDING` and do not credit wallet.
3. No Admin UI or Admin confirmation workflow.
4. Password reset request storage exists, keeps at most one active reset token per account, but email delivery/reset-link consumption is not implemented in Work 04.
5. Credentials authentication uses Auth.js JWT session + database `sessionVersion` revalidation rather than Auth.js database sessions; reason documented in `AUTH_IMPLEMENTATION.md`.
6. `package-lock.json` must be regenerated by the first successful `npm install` after these dependency changes and committed before final acceptance.
7. New registrations correctly start with a zero wallet; because Work 04 intentionally has no payment/Admin confirmation path, end-to-end purchase testing uses the ledger-funded development seed account.
8. Final migration/seed/integration/persistence evidence is pending a machine with PostgreSQL and the Work 04 npm dependencies installed. An install attempt in this execution environment timed out because external npm access is unavailable; no PASS is inferred from static checks.
